# JStart 背景与毛玻璃 UI 移植计划

日期：2026-09-14  
状态：首版已实施，等待 Chrome 扩展环境实测。

实施说明：在后续“简单优先”的要求下，首版保留了统一的背景挂载接口，
Ghost Fibers 则直接使用原生 WebGL 2，未引入 OGL。本项目只需要一个全屏
三角形和一段着色器，这样能省掉依赖下载、打包及版本管理；新增其他背景时
仍可在 `backgrounds/index.js` 中注册各自实现，无需与 Ghost Fibers 使用同一底层引擎。

## 1. 目标与实施边界

在现有 HTML、CSS、JavaScript 架构上，为新标签页接入可切换的 React Bits 背景，并将新标签页及网页内的搜索面板改为毛玻璃风格。

首版采用以下范围：

- 新标签页：可切换 Ghost Fibers、Letter Glitch、Soft Aurora、Floating Lines、Light Pillar、Light Rays、Galaxy 背景，配合毛玻璃搜索面板和使用说明。
- 普通网页：继续显示当前网页，以较厚的深色玻璃搜索面板保证可读性；不加载背景绘图库、不创建背景画布。
- 保留当前搜索、书签、标签页、历史、自定义命令、快捷键及输入法行为。
- 设置页新增背景样式和“动态 / 静态”选项，默认 Ghost Fibers 动态背景；减少动态效果的系统偏好优先。
- 首版不加入折射扭曲、鼠标追光、主题编辑器或完整设置页重设计。

验收以实际 Chrome 扩展环境为准。当前仓库说明主要使用环境为 macOS；Windows 不作为首版已验证平台。

## 2. 已确认的代码结构

| 部分 | 当前实现 | 移植影响 |
| --- | --- | --- |
| 新标签页入口 | manifest.json 指向 redirect.html，再由 redirect.js 跳到 newtab.html | 保留跳转流程，统一两页底色，避免灰色闪屏 |
| 新标签页背景 | newtab.html 中的 SVG，配合 svg.css | 替换成固定背景容器；清理旧背景的引用 |
| 页面脚本 | newtab.js 目前只有注释 | 用于初始化背景、读取设置与管理生命周期 |
| 搜索界面 | content.js 创建 Shadow DOM，并在内部加载 jstart.css | 毛玻璃样式必须写入这份样式，通过内部场景标记区分新标签页与网页 |
| 搜索遮罩 | jstart.css 中背景为 rgba(0,0,0,.7) | 新标签页降低遮罩强度，避免蓝紫色被盖黑 |
| 搜索面板 | 当前深色背景透明度 .72，圆角 8px，没有背景模糊 | 调整底色、边框、圆角和背景滤镜 |
| 显示与关闭 | insertHTML() 创建搜索界面，removeHTML() 删除整个 Shadow host | 背景独立于搜索界面，关闭搜索不重建或销毁背景 |
| 说明页 | setNewTabGuideVisible() 切换 body 类名 | 保留该流程，检查说明文字在亮光带上的可读性 |
| 旧背景联动 | content.js 就绪后修改 jstart-curveWrap 的透明度 | 移除这一旧背景专用逻辑 |

新标签页与普通网页目前共用搜索样式。不能仅改 newtab.css，也不能仅把截图的 3% 白色底色应用到所有网页。

## 3. 技术方案

### 3.1 背景实现

采用“保留着色器，移除 React 与 OGL 包装”的方式：

1. 记录 React Bits 的来源、获取日期和原始文件路径。
2. 保留 Ghost Fibers 的顶点与片元着色器，先以原始默认参数验证视觉一致性。
3. 使用一个全屏三角形和原生 WebGL 2 完成绘制。
4. 将 useRef/useEffect 转成普通初始化函数、事件监听与清理函数。
5. newtab.js 以模块方式使用背景控制器；现有 content.js 保留当前加载方式。
6. 所有运行时代码随扩展本地打包，符合 Manifest V3 的脚本策略。

推荐新增的内部接口：

```js
const background = createGhostFibers(container, options)
background.setPaused(true)
background.destroy()
```

接口为计划约定，实施时可根据静态模式与恢复逻辑调整。初始化失败返回可处理的失败状态，不能阻断搜索界面。

Ghost Fibers 只需要一个全屏三角形，因此原生 WebGL 的接入代码很小，也不需要新增运行时依赖。不同背景仍可在统一挂载接口后采用自己的绘图库。

### 3.2 页面层次

由下至上：

1. 深蓝紫 CSS 渐变底色，页面加载时即存在，也是绘图失败时的兜底。
2. Ghost Fibers 画布，只占新标签页背景容器。
3. 轻微暗角或亮度控制，优先用着色器已有参数实现。
4. 使用说明区域。
5. Shadow DOM 中的搜索遮罩与毛玻璃面板。

背景设置 pointer-events: none 和 aria-hidden，不接受焦点，也不拦截点击。禁止对覆盖搜索框的父层整体使用 opacity 来实现淡入，避免文字一起变淡或影响背景滤镜的采样范围。

### 3.3 两种搜索面板

在 content.js 创建搜索容器时增加明确场景标记，例如 data-surface="newtab" 或 "webpage"。在 Shadow DOM 内的 jstart.css 用局部 CSS 变量配置样式。

| 属性 | 新标签页 | 普通网页 |
| --- | --- | --- |
| 面板底色 | 以截图的白色 3% 为起点，按实际可读性调整 | 使用更厚的深色半透明底色 |
| 背景模糊 | 以 18px 为起点 | 以 18px 为起点，性能验证后调整 |
| 饱和度 | 以 140% 为起点 | 适度降低，避免网页自身颜色过强 |
| 边框 | 1px、白色约 8% | 同风格，必要时增强 |
| 圆角 | 以 14px 为起点 | 与新标签页统一 |
| 全屏遮罩 | 大幅减弱现有 70% 黑色 | 保留足以压低网页干扰的暗色遮罩 |

这些数值是调试起点。使用相同的字体、间距、图标尺寸、选中态和焦点态形成一致风格；输入区域本身保持透明，由外层面板提供玻璃效果。

整个搜索面板只使用一层背景模糊，结果行不再各自叠加模糊。处理长标题、长 URL、滚动条、加载态、鼠标悬停与键盘选中。支持背景滤镜失败时使用更实的底色。

## 4. 生命周期与性能控制

### 4.1 首版参数

| 参数 | 计划默认值 | 目的 |
| --- | --- | --- |
| 帧率上限 | 30 FPS | 适合缓慢装饰动画，减少绘制次数 |
| 渲染像素倍率 | 1 | 不随 Retina 自动翻倍 |
| 纤维层数 | 4 | 与原始默认复杂度一致 |
| 动画速度 | 0.2 | 先保留原始节奏，再做视觉调整 |
| 隐藏标签页 | 停止动画循环 | 消除持续后台绘制 |
| 系统减少动态效果 | 绘制静态画面 | 遵守系统偏好 |
| 用户静态模式 | 绘制固定时刻的一帧 | 保留相同风格，停止持续动画 |

30 FPS 是目标上限，并不承诺所有设备都能达到。动画速度参数不用于节能；真正影响绘制负载的是帧率、像素数量和层数。像素倍率从 2 降至 1，像素数量为原来的四分之一，但整机功耗不会因此严格降为四分之一。

### 4.2 状态规则

- 新标签页先显示 CSS 底色和搜索界面；不让输入焦点等待背景初始化完成。
- 动态模式、页面可见且系统允许动态效果时，启动唯一的动画循环。
- 页面隐藏时取消循环；恢复时重置计时基准，避免动画突然跳跃。
- 静态模式下不保持 requestAnimationFrame 循环，窗口尺寸变化时允许重绘静态帧。
- 关闭搜索框后，背景继续按页面自身状态运行，说明区域显示；重新唤起搜索不能新增画布或动画循环。
- 通过 pagehide/pageshow 处理页面离开与恢复，包括返回缓存情形，避免只销毁而不能恢复。
- destroy 清理动画帧、ResizeObserver、事件监听和 GPU 资源，允许安全重复调用。
- WebGL 初始化失败或上下文丢失时显示 CSS 兜底；恢复后只创建一套资源，反复失败时保持静态兜底，不无限重试。
- 系统动态偏好和扩展背景设置变化后，已打开的新标签页及时更新。

### 4.3 先测量，再降级

首版提供可预测的动态/静态模式，不加入持续运行的复杂自动调档系统。若默认设置在目标机器上不足，再依次尝试像素倍率 0.75、24 FPS 或更少层数，比较观感后确定默认值。

## 6. 分阶段实施与完成标准

### 阶段 A：建立基线与固定来源

- 保存当前新标签页、空搜索框、有结果列表和普通网页唤起效果的截图。
- 记录目标机器、Chrome 版本、窗口尺寸、屏幕缩放与硬件加速状态。
- 取得背景源码，记录来源并检查实际许可。
- 测量当前唤起、输入、空闲资源使用情况。

完成标准：能复现当前效果，并明确哪些源码被移植、如何重新生成依赖成品。

### 阶段 B：先接入背景

- 完成独立控制器与原生 WebGL 2 绘制。
- 替换新标签页背景，处理首屏底色、尺寸变化、静态状态与失败兜底。
- 保持原始视觉参数验证移植正确，再改成 30 FPS 默认上限。
- 检查 CSP、资源路径、重复初始化和退出清理。

完成标准：无 React 依赖地显示目标纤维效果；离线可显示；失败不影响输入搜索。

### 阶段 C：调整毛玻璃 UI

- 接入 Shadow DOM 内的场景标记及样式变量。
- 分别调试新标签页和普通网页的遮罩、底色、模糊、边框和圆角。
- 调整结果列表、加载态、选中态、文字与图标对比度。
- 检查说明区域、短窗口、窄窗口和长列表。

完成标准：背景透色自然，文字始终清楚；菜单展开时仍像同一块面板；操作布局不溢出屏幕。

### 阶段 D：设置与生命周期收尾

- 添加动态/静态设置，设定缺省值和非法值回退。
- 验证设置保存、重新打开和多个新标签页同步变化。
- 完成隐藏暂停、减少动态效果、上下文丢失及页面恢复处理。

完成标准：用户可以长期选择静态，系统偏好得到执行，后台没有持续绘图循环。

### 阶段 E：验证与交付

- 执行下面的功能、视觉和性能验收。
- 清理旧 SVG 资源，补充来源说明、界面截图和使用文档。
- 交付改动清单、实际测试环境、性能对比及仍存在的限制。

阶段按顺序实施并各自验证；不在本次计划阶段修改应用功能或执行提交。

## 7. 验收清单

### 7.1 搜索功能回归

- 新标签页自动唤起并聚焦；Esc 和空白处点击关闭，说明区域出现。
- Cmd+J 与插件图标反复唤起/关闭，事件和节点不累积。
- 中文输入法组合输入正常，候选确认不误触搜索。
- 空输入 Tab 切换引擎；有结果时方向键和 Tab 选择正确。
- Enter 当前页打开，Cmd/Ctrl+Enter 新页打开，末尾空格搜索语义正确。
- /b、/t、/h、自定义命令及忽略书签目录继续生效。
- 搜索加载态与错误情况下，搜索界面仍可操作。
- 搜索展开时网页快捷键拦截、关闭后恢复保持原有行为。

### 7.2 视觉与兼容性

- 在深色、浅色、高对比图片背景网页上检查普通网页模式。
- 检查 1440×900、1920×1080，以及 800×600 等短窗口；另测窄窗口布局。
- 检查浏览器缩放 100%、125%、150% 和外接高分辨率屏幕（具备设备时）。
- 检查输入为空、长结果、无结果、滚动到末尾、键盘选中和鼠标悬停。
- 截图对比原始 Ghost Fibers 观感，重点检查颜色、纤维密度、光带和玻璃边缘。
- 验证 Shadow DOM 内滤镜能采样预期背景，排查祖先的 opacity/filter 等采样边界影响。
- 禁用 WebGL或模拟上下文丢失时保留静态底色；不支持背景滤镜时文字仍清楚。

### 7.3 性能测量

在同一机器、窗口尺寸和供电状态下，每个场景预热约 10 秒后观察 60 秒，至少记录三组：

| 对照场景 | 重点 |
| --- | --- |
| 当前版本 | 原始基线 |
| 新版静态背景 + 毛玻璃 | 分离 UI 与模糊开销 |
| 新版动态背景 + 毛玻璃 | 测量完整效果 |

记录帧率/帧间隔、主线程长任务、Chrome 任务管理器中的 CPU 与内存，以及可获得的 GPU 进程指标。GPU 进程可能由多个页面共享，不能直接把其全部占用归因于 JStart；限制其他活动并结合页面录制分析。

追加验证：

- 切后台 60 秒后，JStart 背景绘制计数不再增长（设置或尺寸变化触发的单次重绘单独计数）。
- 打开多个新标签页，隐藏页面不持续绘制；两个窗口同时可见时记录叠加开销。
- 连续开关搜索面板 30 次，无新增背景画布、重复动画循环或持续增长的监听器。
- 连续缩放窗口，无黑屏、拉伸残留或明显内存增长趋势。
- 静态模式空闲时无动画循环；普通网页搜索不创建 Ghost Fibers WebGL 上下文。
- 对比输入与唤起延迟，背景相关新增主线程长任务超过 50ms 时定位处理；GPU 初始化耗时单独记录。

验收目标：目标设备上默认档位尽量稳定接近 30 FPS，输入与键盘操作不出现可感知退化；如不满足则调整参数并复测。不给出未经实测的固定 CPU 占用、功耗或内存承诺。

## 8. 工作量与主要不确定性

在目标 Chrome 环境可测试、依赖获取正常的情况下，按熟悉现有代码的开发者估算：

| 工作 | 估算 |
| --- | --- |
| 来源固定、基线记录与独立背景移植 | 2–4 小时 |
| 毛玻璃、列表和两场景视觉调整 | 2–4 小时 |
| 设置、生命周期与失败恢复 | 1–3 小时 |
| 扩展回归、性能测量与文档 | 2–4 小时 |
| 总计 | 约 7–15 小时，通常为 1–2 个工作日 |

这是计划估算，不是运行时间承诺。最可能增加时间的是 Shadow DOM 背景滤镜实际效果、上下文恢复、高分辨率性能与视觉调参。背景算法本身已经存在，主要工作在接入和验证。

若默认动态效果不符合性能目标，先降低渲染参数或选择静态纤维画面；背景控制器与搜索独立，可停用动态模块而保留毛玻璃 UI。每个阶段保持改动边界清楚，便于按文件恢复。

## 9. 实现依据

- [Ghost Fibers 原始组件](https://github.com/DavidHDev/react-bits/blob/main/src/content/Backgrounds/GhostFibers/GhostFibers.jsx)：OGL、WebGL 2、着色器、默认参数及暂停机制。
- [React Bits 演示面板](https://github.com/DavidHDev/react-bits/blob/main/src/components/common/Preview/BackgroundContent.jsx)：截图对应的半透明底色、边框、14px 圆角，以及 blur(18px) saturate(140%)。
